## Rollback and emergency runbook

1. **Site:** in the Appwrite Console, reactivate the immediate previous healthy deployment; verify `/login`, anonymous `/dashboard`, one authenticated read, and no console/hydration errors. Do not change schema or data during an application rollback.
2. **Function:** disable the maintenance schedule for containment, or reactivate the previous healthy Function deployment if one exists. Keep client execute permission empty. Re-enable only after an authorized dry inspection and one healthy execution.
3. **Schema:** preserve additive Schema V4. Never perform a destructive schema downgrade for an application rollback.
4. **Data:** use `scripts/appwrite-restore.mts` only under explicit incident authorization. Verify the chosen external backup first, prefer a disposable/empty target for drills, and never overwrite meaningful production data merely to prove tooling.
5. **Operator access:** retain bootstrap, provisioning, and backup credentials outside the Site and outside Git. Use the least-scoped local credential for the named recovery action, record only sanitized results, then revoke temporary credentials where applicable.
6. **Emergency order:** contain frontend writes by rolling back/pausing the Site, disable maintenance only when its behavior is implicated, take and verify a fresh external backup, diagnose from sanitized provider evidence, then restore data only with explicit authorization.
