How to review these images

The direction is compact, readable mobile layouts using the established pearl / blue-gray palette. Keep all existing fields, modules, exact poisha values, confirmations, permissions and routes. Reduce padding and duplicate visual framing, rather than removing information.

Generated images are illustrative. The full audit lists remaining illustration differences, including category assets, navigation selection, Card/member permissions, attribution and sample chart data. Existing source and frozen requirements remain authoritative. No application source, desktop CSS, dependency, production record or provider configuration was changed.

Design constraints and illustration corrections
  • Icon-only five-destination bottom navigation remains. Visible labels need a separate requirement change.
  • Mobile Filters sheet is a proposed presentation change: keep all filters live and preserve existing Clear Filters behavior.
  • All 12 real category assets and their order remain; sample generated glyphs are not replacement assets.
  • Payer is read-only. Members cannot rename/remove/transfer/delete or handle leader join requests. Ignore incidental generated chevrons or overflow icons.
  • Use the existing six Card designs and demo constants. Card Name has no new length maximum.
  • House codes always have exactly nine digits. Attribution uses existing exact authors and links; credits remain standalone.
  • Charts use actual derived data. Generated bars, dates, record counts and history are fictional visual examples.
  • Auth uses existing allowlisted self-signup, no manual approval process. Actual copy and password rules stay unchanged.
  • Content below an image's visible portion is retained, including Dashboard analytics and Monthly Report settlement sections.
